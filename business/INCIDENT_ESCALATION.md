# 2060 Incident & Escalation Process

## Severity 1 — Critical

Examples:
- Production system unavailable
- Major security incident
- Serious data loss

Action:
1. Stop non-essential changes.
2. Identify the problem.
3. Protect affected systems/data.
4. Restore service where possible.
5. Document the incident.
6. Notify affected stakeholders when appropriate.

## Severity 2 — Major

Examples:
- Important feature unavailable
- Significant performance problem
- Customer unable to complete an important workflow

Action:
1. Investigate.
2. Create a temporary workaround if possible.
3. Fix and test the issue.
4. Document the resolution.

## Severity 3 — Normal

Examples:
- Minor bug
- UI issue
- Documentation problem

Action:
1. Record the issue.
2. Prioritize it.
3. Fix during normal development.

## Security

Never place passwords, API keys or private customer information
in source code or public repositories.

## Post-Incident Review

For significant incidents record:
- What happened
- When it happened
- Impact
- Root cause
- Resolution
- Preventive action
